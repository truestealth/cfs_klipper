# cfs_box

[English](README.md) | Русский

Открытая замена штатного модуля Klipper `[box]` для Creality K1C с K1 Series CFS
Upgrade. Сохраняем прошивку MCU CFS, экран, Creality Print, статус Fluidd,
маппинг слайсера и пользовательские настройки.

Существующая хостовая библиотека `serial_485` сохраняется. Объём работы — полный
штатный контракт `box`: инициализация, загрузка, выгрузка, резка, смена и продувка,
пауза/продолжение, ошибки/восстановление, датчики, RFID и данные катушек.

Базовая прошивка MCU нашего CFS — **1.1.3**. В
[истории изменений прошивки](docs/compatibility.ru.md#firmware-history) описаны
изученные отличия до 1.5.3 и их значение для совместимости.

**Статус:** состояние, конфигурация, совместимое хранение, интеграция native-вызовов,
разбор ответов и версии отдельных устройств реализованы и проверены на ПК.
Механические операции CFS ещё предстоят. Точка входа отклоняет активацию
до получения объектов принтера. Установщика и готовой для принтера версии нет.

## Структура проекта

```text
src/cfs_box/     Реализация расширения
klipper/box.py  Тонкая точка входа Klipper
tests/          Проверки на ПК
docs/           Архитектура, протокол и совместимость
```

Этап 1 дал матрицу полного контракта. Этап 2 добавил состояние, настройки,
хранение и девять обработчиков команд данных. Этап 3 добавляет вызовы сохранённого
native API, проверку ответов, точные профили прошивок и двенадцать обработчиков
native-команд, проверенные через подставные объекты Klipper. Жизненный цикл
и обработка операций реализуются на следующих этапах.

- [Архитектура](docs/architecture.ru.md): ответственность и размещение в Klipper.
- [Протокол](docs/protocol.ru.md): кадры, граница native API и открытые вопросы.
- [Совместимость](docs/compatibility.ru.md): покрытие реализации и проверок.
- [План реализации](docs/implementation-plan.ru.md): этапы и критерии готовности полного контракта `box`.
- [Матрица контракта](docs/contract-matrix.ru.md): полный перечень и связи с планируемыми проверками на ПК/оборудовании, включая существующие G-code макросы.

## Быстрый старт

Тесты запускаются прямо из рабочей копии стандартным `unittest`, без установки
расширения и дополнительных Python-зависимостей. Исходники рассчитаны на Python
3.8 или новее. Совместимость с native-средой MIPS и принтером пока не проверена.

Windows / PowerShell:

```powershell
python -m unittest discover -s tests -v
```

Linux / macOS:

```sh
python3 -m unittest discover -s tests -v
```

Тесты покрывают снимки состояния и remap, все 53 настройки и 21 поле endpoint,
команды данных, временные файлы, native-запросы и ответы, разные версии устройств
и устаревшие действия, загрузчик и целостность матрицы. Они не исполняют штатный
native-бинарник и не управляют оборудованием. См. [покрытие и намеренные отличия
хранения](docs/compatibility.ru.md#state-configuration-and-storage)
и [ограничения native-интеграции](docs/protocol.ru.md#native-integration).

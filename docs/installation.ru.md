# Подготовка локальной установки

[English](installation.md)

Инструмент копирует расширение в локальный каталог Klipper `extras`. Загрузчик
запускает пассивный допуск с блокировкой механики. Проба на контрольном K1C с
MCU CFS 1.1.3 и Python 3.8.2 принтера вышла в ready и сохранила устойчивое чтение
идентификатора/состояния через native API. Приёмка механики остаётся отдельной.
Сам инструмент не подключается к принтеру, не управляет службами и не изменяет
конфигурацию, макросы, прошивку или данные; удалённая установка и перезапуск
требуют отдельного разрешения.

Запускайте из этой копии проекта с Python 3.8 или новее. Оба пути обязательны;
каталог extras и родительский каталог резервной копии должны существовать.
Сам путь резервной копии должен отсутствовать и находиться отдельно от extras.
Нужен существующий обычный `extras/box.py`; `extras/cfs` должен отсутствовать.
Ссылки, точки повторной обработки и переходы к родительскому каталогу запрещены.
Нативные точки входа `box.so`, `box.*.so`, `box.pyd` и `box.*.pyd` запрещены,
поскольку они могут перекрывать `box.py`; `box_wrapper.so` сохраняется.
Действие по умолчанию только показывает план:

```sh
python tools/install.py --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py install --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py restore --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
```

Установка сохраняет исходные байты `box.py`, права и временные метки вместе с
манифестом хешей, затем копирует только фиксированный список файлов Python.
Поддерживаются оба размещения кеша точки входа:
`extras/__pycache__/box.cpython-*.pyc` и соседний `extras/box.pyc`, который
использует контрольный принтер. Исходные кеши сохраняются и удаляются перед
заменой исходного файла; восстановление удаляет созданные соответствующие кеши
и возвращает исходные байты, права и временные метки. Если кеша изначально не
было, созданный соответствующий кеш удаляется при откате. Остальные записи
кеша не изменяются.
Существующие `box*.so`, `serial*.so`, остальные extras и данные пользователя не
изменяются. Восстановление проверяет резервную копию и все установленные файлы
и отказывает при их изменении или наличии дополнительных записей в `cfs`, кроме
распознанного байткода установленных модулей: `cfs/<module>.pyc` и соответствующих
файлов в `cfs/__pycache__`. Удаляются только эти собственные кеши. Неизвестные
записи кеша и ссылки запрещены.
Восстановленные байты проверяются, резервная копия сохраняется. Берегите её:
хеши обнаруживают случайные изменения, но не подтверждают подлинность
умышленно изменённого манифеста.

Новые копии используют версию 3 манифеста. Копии версии 2 с современным размещением
кеша по-прежнему восстанавливаются. Копия версии 2 с соседним `extras/box.pyc`
отклоняется до изменений: старый манифест не позволяет установить, был ли этот
файл исходным или созданным при запуске. Для прежнего неоднозначного размещения
сохраните исходники и свидетельства кеша и используйте отдельно проверенную
процедуру восстановления.

При ошибке установки инструмент пытается отменить уже сделанные изменения;
каталог резервной копии остаётся для проверки. При ошибке восстановления может
понадобиться ручное восстановление из `box.py.original`; не удаляйте его. Во
время операций никто другой не должен изменять целевой каталог: инструмент не
блокирует другие процессы и не обеспечивает транзакцию при потере питания.

Остановите целевой процесс Klipper перед установкой или восстановлением, затем
проверьте записанные файлы и резервную копию до запуска. Сначала изучите настоящий
service wrapper: в исследованной прошивке ветка start/restart может копировать
заводскую конфигурацию и перезапускать ещё одну службу MCU. Эти действия не
входят в файловый установщик.

<a id="passive-startup"></a>

## Пассивный первый запуск

`load_config(config)` теперь возвращает объект `box` вместо безусловного отказа.
Он получает абсолютный корень данных из сохранённого скалярного значения
`extras.base_info.base_dir`, требует `gcode` и `webhooks` и поручает Klipper
загрузить `serial_485 <bus>` по `[box] bus`. Загрузчик не импортирует native-бинарник
напрямую и не открывает второе serial-соединение. Настроенный датчик резака
использует сохранённый объект `buttons`.

На `klippy:ready` жизненный цикл получает `toolhead`, `gcode_move`, `print_stats`,
`virtual_sdcard`, настроенный датчик головы, сохранённую таблицу из четырёх
элементов `extras.auto_addr_wrapper.addr_manager_table_mb` и `greenlet.getcurrent`.
Рабочая конфигурация адресатора должна оставаться включённой; настроенный lookup
Box не меняет собственные требования адресатора к bus.
Затем он заимствует настроенный serial-объект, отправляет `box:ready` и планирует
heartbeat. Неудачная попытка ready отменяет собственные задачи расширения
и снимает native-привязку, не закрывая штатный транспорт.

Точка входа явно задаёт контекст первого поколения `cfs0` для адресов 1–4.
Это поддерживаемая целевая система K1 CFS Upgrade, а не распознавание оборудования
по ответу версии. По-прежнему нужен точный профиль прошивки с базовой 1.1.3;
замена серийного номера снимает подтверждение семейства.

По умолчанию допуск разрешает только typed-запросы `GET_RFID` (`0x02`), `GET_REMAIN_LEN` (`0x03`),
`GET_BUFFER_STATE` (`0x05`), `GET_FILAMENT_SENSOR_STATE` (`0x08`), `GET_BOX_STATE`
(`0x0A`) и `GET_VERSION_SN` (`0x14`). Запросы колеса, raw-диагностика,
`CREATE_CONNECT`, записи моторов/preload и действия хоста отклоняются. Входящие
события ошибок/runout/головы не запускают паузу, восстановление движений, нагрев,
подтягивание или G-code включения датчика. Автоматическое разрешение preload
и power-on RUN подавлены. Существующие макросы могут получать эти явные ошибки
допуска; режим не подходит для печати. Общего переключателя механики нет.
Отдельный явный тест ниже разрешает одну операцию, сохраняя пассивный
жизненный цикл.

Для телеметрии используйте прямые типизированные команды чтения.
`BOX_INFO_REFRESH` вызывает preload RUN, а существующие температурные обёртки
могут начать нагрев до защищённого обработчика Box. Пассивный Box не отключает
G-code других подсистем.

После идентификации каждая пассивная инициализация читает свежую маску присутствия
MATERIAL перед переносом сохранённых меток в живое состояние, включая reconnect
и адреса, заранее отмеченные штатным адресатором как подключённые. Диагностика
пассивного режима использует `Lifecycle.last_error`, сохраняя без изменений
наблюдаемый штатным virtual SD признак паузы `box.last_err`.

Кэш катушек остаётся в `<base_dir>/creality/userdata/box/tn_data.json`, рядом
расположен `material_database.json`; маркер продувки остаётся в
`<base_dir>/creality/userdata/config/flushing_sign`. Существующие корректные
данные кэша загружаются, повреждённые вызывают ошибку. Ответы RFID и остатка
используют прежнее сохранение метаданных: даже запрос чтения может переписать
совместимый кэш при равных значениях. При отсутствии файла или `base_data`
создаётся совместимый пустой кэш. Пассивный допуск поэтому не означает хранилище
только для чтения; явные команды данных/настроек также могут сохранять данные.
`SAVE_BOX_CFG` использует заводские пути
`/usr/data/printer_data/config/box.cfg` и `/mnt/UDISK/printer_data/config/box.cfg`;
корень данных их не перенаправляет.

Проверки отказов на ПК используют подстановки и временные пути. Первая проба на
контрольном принтере также сверила активную цепочку include и все 54 настройки,
сохранила хеши защищённых файлов и получила 103 корректных native-ответа за семь
минут. Это ограниченные пассивные наблюдения, а не приёмка механики или другой
версии прошивки.

Затем основной установщик версии 3 выполнил реальное восстановление файлов/кэша
и повторную пассивную установку на этом принтере. При остановленном Klipper
сверены исходные байты точки входа и кэша, режим доступа и mtime с наносекундной
точностью; принадлежащий расширению пакет и его кэши удалены. Штатный процесс Box
между восстановлением и установкой не запускался, чтобы не выполнять его
автоматические стартовые действия. Пассивные запуски после установки вышли
в ready. Для новых резервных копий версии 3 отдельный адаптер старого кэша
не нужен. Проверен откат файлов; запуск штатного процесса после отката
и приёмка механики остаются непроверенными.

После прямых запросов RFID/остатка экран и Creality Print видели CFS, но показывали
все четыре слота серыми или неопределёнными. Изменённый кэш сохранили в резервную
копию, затем при остановленном Klipper точно вернули кэш катушек до запросов.
Пассивный запуск тех же исходников восстановил отображение в обоих интерфейсах,
что подтвердил пользователь. Декодер/runtime не исправлялись, запросы RFID/остатка
не повторялись. Проверено отображение кэша, а не получение свежего RFID
с физических меток; RFID и остатки восстановлены вместе.

<a id="single-operation-trial"></a>

## Явный допуск к одной пробной предзагрузке

Этот путь подготовлен и проверяется только на ПК. На принтер он не устанавливался
и не запускался. Будущие установка и механическая проба требуют отдельного
разрешения и физической подготовки. Жизненный цикл по умолчанию остаётся пассивным.
До любой разрешённой будущей пробы сохраните резервную копию кэша катушек.

Собственная команда расширения — `CFS_TEST_PRELOAD TNN=T1A CONFIRM=1`. `TNN`
должен указывать один физический слот от T1A до T4D; изменяемый маппинг инструментов
не используется. `CONFIRM=1` обозначает явный вызов, а не аутентификацию оператора.
Постоянного состояния готовности к запуску или общего переключателя механики нет.
Штатные host-команды и автоматические пути ready, heartbeat, reconnect, головы,
runout и ошибок сохраняют пассивные ограничения на всё время теста.

Перед RUN требуются готовая подключённая cfs0 MCU **1.1.3**, кодировка хоста 1,
состояние печати standby, неактивный virtual SD, отсутствие паузы/ошибки/другой
операции и настоящий настроенный датчик головы без филамента. Свежие обычные
ответы запрашиваются в следующем порядке:

1. `GET_BOX_STATE`: режим IDLE (`0`).
2. `GET_FILAMENT_SENSOR_STATE`, MATERIAL: выбранный слот занят материалом.
3. `GET_FILAMENT_SENSOR_STATE`, CONNECTIONS: вся маска равна нулю.
4. Один запрос `SET_PRE_LOADING` RUN (`0x0D`) с одним битом выбранного слота.
5. Повторный `GET_BOX_STATE`: снова IDLE (`0`).
6. `GET_RFID` только для выбранного слота.
7. `GET_REMAIN_LEN` только для выбранного слота.

Разрешение принадлежит текущему кооперативному контексту исполнения, жизненному
циклу, native-привязке, поколению устройства и конкретному объекту запроса. Оно
используется один раз и отзывается при завершении или отказе. Контекст проверяется
вокруг ожиданий и перед native-попытками/эффектами; срок кооперативного исполнения —
300 секунд. Чтения используют таймаут две секунды, RUN ограничен оставшимся
временем теста. Эти ограничения не прерывают ожидание внутри штатной библиотеки.
Отсутствующий ответ, ненулевой статус, событие, не-IDLE и неверный
payload завершают тест без следующих шагов. До сохранения метаданных RFID-ответ
должен содержать ровно выбранный слот со значением `none`, `unknown` или записью
из 40 байтов.

В MCU 1.1.3 RUN может подготовить общий хаб до обработки выбранного слота.
Требование нулевой CONNECTIONS исключает наблюдаемую ветку втягивания занятых
каналов в момент этого снимка; оно не гарантирует физическую изоляцию и не
отключает автономное поведение MCU. ACK RUN может прийти после истечения
внутреннего ожидания, поэтому сам по себе не подтверждает завершение механики;
следующий свежий ответ IDLE обязателен.

Хост не повторяет тестовые запросы после ошибок MCU CRC/LENGTH. Передача
`retries_en=False` не отменяет повторы, которыми уже владеет штатный `.so`.
Отзыв разрешения или истечение кооперативного срока запрещают дальнейшую работу
хоста, но не являются физической остановкой уже исполняющейся native/MCU-операции.
Неподтверждённые команды очистки CLOSE/STOP не отправляются. Результаты и запись
кэша сохраняют обычную семантику RFID/остатка, включая `unknown` и базовую
подстановку `100`.
Если RFID-метаданные уже сохранены до отказа следующего запроса остатка, они
остаются сохранёнными: тест не восстанавливает прежние значения кэша.
Проверки на ПК не подтверждают считывание RFID, завершение
механики или аппаратную приёмку. Другие host-действия, нагреватели и движения
головы разрешения не получают.

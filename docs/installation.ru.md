# Подготовка локальной установки

[English](installation.md)

Проверенный на ПК инструмент копирует расширение в локальный каталог
Klipper `extras`. Загрузчик запускает пассивный допуск с блокировкой механики. Компонентные
тесты не подтверждают готовность принтера; для будущей проверки на принтере
потребуются отдельное разрешение и проверка оборудования. Инструмент не
подключается к принтеру, не управляет службами и не изменяет конфигурацию,
макросы, прошивку или данные.

Запускайте из этой копии проекта с Python 3.8 или новее. Оба пути обязательны;
каталог extras и родительский каталог резервной копии должны существовать.
Сам путь резервной копии должен отсутствовать и находиться отдельно от extras.
Нужен существующий обычный `extras/box.py`; `extras/cfs` должен отсутствовать.
Ссылки, точки повторной обработки и переходы к родительскому каталогу запрещены.
Нативные точки входа `box.so`, `box.*.so`, `box.pyd` и `box.*.pyd` запрещены,
поскольку они могут перекрывать `box.py`; `box_wrapper.so` сохраняется.
Действие по умолчанию только показывает план:

```sh
python tools/install.py --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py install --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py restore --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
```

Установка сохраняет исходные байты `box.py`, права и временные метки вместе с
манифестом хешей, затем копирует только фиксированный список файлов Python.
Соответствующие файлы CPython `extras/__pycache__/box.cpython-*.pyc` сохраняются
и удаляются перед заменой исходного файла; восстановление удаляет созданные
соответствующие кеши и возвращает исходные байты, права и временные метки.
Остальные записи кеша не изменяются.
Существующие `box*.so`, `serial*.so`, остальные extras и данные пользователя не
изменяются. Восстановление проверяет резервную копию и все установленные файлы
и отказывает при их изменении или наличии дополнительных записей в `cfs`, кроме
обычных файлов байткода CPython установленных модулей в `cfs/__pycache__`:
они удаляются. Неизвестные записи кеша и ссылки запрещены.
Восстановленные байты проверяются, резервная копия сохраняется. Берегите её:
хеши обнаруживают случайные изменения, но не подтверждают подлинность
умышленно изменённого манифеста.

При ошибке установки инструмент пытается отменить уже сделанные изменения;
каталог резервной копии остаётся для проверки. При ошибке восстановления может
понадобиться ручное восстановление из `box.py.original`; не удаляйте его. Во
время операций никто другой не должен изменять целевой каталог: инструмент не
блокирует другие процессы и не обеспечивает транзакцию при потере питания.

<a id="passive-startup"></a>

## Пассивный первый запуск

`load_config(config)` теперь возвращает объект `box` вместо безусловного отказа.
Он получает абсолютный корень данных из сохранённого скалярного значения
`extras.base_info.base_dir`, требует `gcode` и `webhooks` и поручает Klipper
загрузить `serial_485 <bus>` по `[box] bus`. Загрузчик не импортирует native-бинарник
напрямую и не открывает второе serial-соединение. Настроенный датчик резака
использует сохранённый объект `buttons`.

На `klippy:ready` жизненный цикл получает `toolhead`, `gcode_move`, `print_stats`,
`virtual_sdcard`, настроенный датчик головы, сохранённую таблицу из четырёх
элементов `extras.auto_addr_wrapper.addr_manager_table_mb` и `greenlet.getcurrent`.
Рабочая конфигурация адресатора должна оставаться включённой; настроенный lookup
Box не меняет собственные требования адресатора к bus.
Затем он заимствует настроенный serial-объект, отправляет `box:ready` и планирует
heartbeat. Неудачная попытка ready отменяет собственные задачи расширения
и снимает native-привязку, не закрывая штатный транспорт.

Точка входа явно задаёт контекст первого поколения `cfs0` для адресов 1–4.
Это поддерживаемая целевая система K1 CFS Upgrade, а не распознавание оборудования
по ответу версии. По-прежнему нужен точный профиль прошивки с базовой 1.1.3;
замена серийного номера снимает подтверждение семейства.

Допуск разрешает только typed-запросы `GET_RFID` (`0x02`), `GET_REMAIN_LEN` (`0x03`),
`GET_BUFFER_STATE` (`0x05`), `GET_FILAMENT_SENSOR_STATE` (`0x08`), `GET_BOX_STATE`
(`0x0A`) и `GET_VERSION_SN` (`0x14`). Запросы колеса, raw-диагностика,
`CREATE_CONNECT`, записи моторов/preload и действия хоста отклоняются. Входящие
события ошибок/runout/головы не запускают паузу, восстановление движений, нагрев,
подтягивание или G-code включения датчика. Автоматическое разрешение preload
и power-on RUN подавлены. Существующие макросы могут получать эти явные ошибки
допуска; режим не подходит для печати. Настройки или G-code для включения
механики сейчас нет.

После идентификации каждая пассивная инициализация читает свежую маску присутствия
MATERIAL перед переносом сохранённых меток в живое состояние, включая reconnect
и адреса, заранее отмеченные штатным адресатором как подключённые. Диагностика
пассивного режима использует `Lifecycle.last_error`, сохраняя без изменений
наблюдаемый штатным virtual SD признак паузы `box.last_err`.

Кэш катушек остаётся в `<base_dir>/creality/userdata/box/tn_data.json`, рядом
расположен `material_database.json`; маркер продувки остаётся в
`<base_dir>/creality/userdata/config/flushing_sign`. Существующие корректные
данные кэша сохраняются, повреждённые вызывают ошибку. При отсутствии файла
или `base_data` создаётся совместимый пустой кэш, поэтому пассивный допуск
не означает файловую систему только для чтения. Явные команды данных/настроек
также могут сохранять данные. `SAVE_BOX_CFG` использует заводские пути
`/usr/data/printer_data/config/box.cfg` и `/mnt/UDISK/printer_data/config/box.cfg`;
корень данных их не перенаправляет.

Все текущие проверки запуска и отказов используют подстановки на ПК и временные
пути. Сверка текущей конфигурации и аппаратная приёмка ещё предстоят; в рамках
этой работы к принтеру не подключались и ничего на нём не меняли.

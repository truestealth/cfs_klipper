# Установка и тестовые команды

[English](installation.md)

Установщик копирует расширение в существующий каталог Klipper `extras`.
Штатная библиотека `serial_485`, прошивка MCU, конфигурация, макросы и данные
пользователя сохраняются. Запуск пассивный; тестовые команды ниже разрешают
по одной явно выбранной операции.

## Установка и откат

Запускайте из рабочей копии на Python 3.8 или новее. Перед установкой или
восстановлением остановите Klipper. Проверьте обёртку службы: её ветка запуска
может копировать заводскую конфигурацию или перезапускать службу MCU.

Каталог extras и родительский каталог копии должны существовать. Путь копии
должен быть новым и находиться вне extras; `extras/box.py` должен быть обычным
файлом, а `extras/cfs` — отсутствовать. По умолчанию выводится план изменений:

```sh
python tools/install.py --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py install --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
python tools/install.py restore --extras /path/to/klipper/klippy/extras --backup /path/to/new-backup
```

Установка сохраняет исходный `box.py` и его кэши, включая соседний `box.pyc`
и `__pycache__/box.cpython-*.pyc`, с хешами, правами и временем изменения.
Затем копирует фиксированный список Python-файлов и сбрасывает кэш точки входа.
Другие extras, native-библиотеки и данные не меняются.

Восстановление проверяет копию и установленные исходники, удаляет собственный
пакет и распознанные созданные кэши, возвращает исходные байты и метаданные точки
входа. Лишние файлы пакета, неизвестные кэши, изменённые исходники, ссылки
и обход каталогов отклоняются. Native-точки входа вроде `box.so` отклоняются,
поскольку могут перекрыть `box.py`; `box_wrapper.so` сохраняется.

Новые копии используют версию манифеста 3. Копии версии 2 с современным кэшем
поддерживаются; версия 2 с соседним `box.pyc` требует отдельно проверенного
восстановления, поскольку манифест не определяет происхождение этого кэша.

Сохраните копию после восстановления и проверьте файлы перед запуском.
Во время операции не должно быть других записывающих процессов: установщик
не блокирует их и не обеспечивает транзакцию при потере питания. При ошибке
установки выполняется попытка отката; если отказало само восстановление,
сохраните `box.py.original` для восстановления.

## Пассивный запуск

`load_config` получает корень данных из `extras.base_info.base_dir` и загружает
`serial_485 <bus>` по `[box] bus`. Расширение использует этот транспорт,
не открывая второе соединение. На `klippy:ready` получает зависимости движения,
печати, датчиков, менеджера адресов и кооперативного диспетчера, отправляет
`box:ready` и запускает heartbeat. Настройка штатного менеджера адресов
должна оставаться включённой.

Точка входа задаёт контекст первого поколения `cfs0` для адресов 1–4.
Версия выбирается по точному профилю прошивки; базовая — **1.1.3**.

Пассивный допуск разрешает типизированные запросы идентификации и телеметрии
`0x02/03/05/08/0A/14`. Обычные механические команды, native-записи и автоматическая
предзагрузка заблокированы; общего переключателя механики нет. Автоматические
события головы, runout и ошибок не запускают движение или нагрев. G-code вне Box
сохраняет своё поведение: `BOX_INFO_REFRESH` включает предзагрузку, а температурные
обёртки могут нагревать до вызова защищённой команды Box.

Кэш катушек остаётся в `<base_dir>/creality/userdata/box/tn_data.json`, рядом
с `material_database.json`. Маркер продувки —
`<base_dir>/creality/userdata/config/flushing_sign`. Перед применением сохранённых
меток читается свежая маска MATERIAL, включая reconnect. Чтение RFID/остатка
и явные команды данных могут сохранять совместимые обновления кэша; пассивный
режим не означает запрет записи данных. `SAVE_BOX_CFG` сохраняет заводские
пути конфигурации.

## Предзагрузка

```gcode
CFS_TEST_PRELOAD TNN=T1A CONFIRM=1
```

`TNN` выбирает физический слот T1A–T4D. Команда требует подключённый cfs0 MCU
**1.1.3**, кодировку 1, ready/standby, отсутствие печати, паузы, активной ошибки
и другой операции, а также настроенный датчик головы без материала.

Последовательность: свежие STATE (режим `0`), MATERIAL (слот присутствует),
CONNECTIONS (ноль), один RUN `SET_PRE_LOADING` выбранного слота, свежий STATE
(режим `0`), затем RFID и остаток этого слота. Метаданные сохраняются только
после проверки соответствующего ответа.

Кооперативный лимит — 300 секунд, чтения — по две секунды; RUN ограничен
оставшимся временем. Хост не повторяет запросы. ACK и телеметрия IDLE
не раскрывают отдельное состояние занятости предзагрузки MCU, поэтому
наблюдайте за материалом во время операции.

## Полная загрузка и выгрузка

```gcode
CFS_TEST_LOAD TNN=T1A CONFIRM=1
CFS_TEST_UNLOAD TNN=T1A CONFIRM=1
```

Это отдельные вызовы: один не запускает другой. Каждый читает настроенный
рецепт `BOX_LOAD_MATERIAL_WITH_MATERIAL` или `BOX_QUIT_MATERIAL`, требует
поддерживаемый порядок фаз и передаёт физический `TNN` фазам подачи.
Существующие макросы сохраняются. Изменённые рецепты или дополнительные
аргументы этим допуском отклоняются.

Перед аппаратной проверкой выполните homing XYZ, проверьте фактическую позицию
и просимулируйте настроенный маршрут. Стол и путь к резаку должны быть свободны.
Вход к резаку требует отпущенного датчика и Y не дальше настроенного безопасного Y.

Обе команды требуют один online cfs0 MCU **1.1.3**, кодировку 1, ready/standby,
неактивную virtual SD, отсутствие паузы/продолжения, активной ошибки, дозаправки,
дренирования и другой операции. Нужен настоящий датчик головы. Позиции, границы
хода, температуры, подача и числа повторов проверяются до нагрева, движения
и native-записей. Конфигурация закреплена на время вызова.

| Наблюдение | LOAD | UNLOAD |
| --- | --- | --- |
| Начальные голова/источник | Голова пустая, загруженного источника нет | Материал в голове; подсказки источника соответствуют `TNN` или обе отсутствуют |
| Свежий режим | IDLE `0` | IDLE `0` или PRINTING `2` |
| Свежий MATERIAL | Выбранный слот присутствует | Выбранный слот присутствует |
| Свежий CONNECTIONS | Ноль | Только выбранный слот |
| Свежий буфер | Нейтральный `0` или пустой предел `2` | Корректное обычное наблюдение |
| Конечный результат | Материал в голове, выбранный CONNECTIONS, режим `2`, буфер не полный, источник записан | Голова пустая, CONNECTIONS ноль, режим `0`, буфер `2`, резак отпущен, источник отсутствует |

LOAD выполняет настроенные проверки, позиционирование подачи, очистку, загрузку
CFS, фазу экструдера, продувку и возврат позиции. Продувка внутри этого вызова
получает `LEN=int(cfg.Tn_extrude)`: 150 мм в базовом профиле. Длина — целое
число 1–200 мм, пары скорости/доли — конечные положительные значения,
эффективная подача — не более 200 мм. Фактические множители скорости и экструзии
должны равняться 1. Отказ подачи останавливает вызов до дальнейшей очистки.

UNLOAD известного источника выполняет настроенные проверки и резку по датчику,
затем BUFFER и блокирующее втягивание головы E−20. Конечная E−30 с F600
(номинально три секунды) отправляется на исполнение до одного выбранного запроса
MATERIAL. После обычного ACK MATERIAL выполняется `M400` до очистки источника
и возврата позиции. Это позволяет втягивать головой во время запроса CFS
без требования одинакового физического момента запуска моторов.

UNLOAD неизвестного источника сохраняет обе подсказки источника пустыми. `TNN`
определяет только единственный канал в свежих CONNECTIONS и MATERIAL.
Зарегистрированная фаза втягивания допускает по порядку свежие CONNECTIONS,
MATERIAL, STATE, IDLE, BUFFER с нулевым селектором и MATERIAL выбранного канала.
Сохраняется настроенная последовательность холодной резки и нагрева;
старый источник не подставляется.

## Втягивание только силами CFS

<a id="native-buffer-trial"></a>

```gcode
CFS_TEST_RETRACT TNN=T1C CONFIRM=1
CFS_TEST_RETRACT TNN=T1C TRIGGER=MATERIAL CONFIRM=1
```

По умолчанию выбран BUFFER; MATERIAL задаётся отдельно явно. Эти команды
не запускают XYZ/E, нагрев или резку и не требуют homing. Сохраняются проверки
устройства, свободного состояния и владения. Подсказки источника должны либо
обе отсутствовать, либо обе соответствовать `TNN`; свежий CONNECTIONS должен
указывать ровно этот канал, а MATERIAL — включать его.

Последовательность: четыре свежих наблюдения (STATE, MATERIAL, CONNECTIONS,
BUFFER), IDLE, свежий обычный STATE, одно выбранное втягивание, затем снова
четыре наблюдения. Только начальный STATE может содержать `0x13` или `0x19`
с четырьмя байтами данных и режимом `4`; последующие ответы должны быть обычными.

BUFFER использует кооперативный лимит 60 секунд и лимит запроса десять секунд.
Конечный режим должен быть `0`, буфер `2`, CONNECTIONS — ноль или выбранный канал;
состояние головы сообщается без требования пустой головы. У MATERIAL лимит
240 секунд и лимит запроса 150 секунд; конечный CONNECTIONS должен быть нулевым,
а голова — пустой. Оба требуют сохранения выбранного материала.
Ни один не назначает и не очищает загруженный источник.

## Выполнение и завершение

`CONFIRM=1` обозначает явный вызов. Допуск принадлежит текущим диспетчеру,
операции, жизненному циклу, привязке и поколению устройства и отзывается
после вызова. Обычные команды и посторонние callbacks не могут его использовать.
Полные LOAD/UNLOAD временно допускают только свои зарегистрированные фазы
и настоящее событие прихода материала для ожидающей загрузки.

Каждый ответ должен быть свежим, обычным и корректным для opcode/стадии
до применения декодером. Ошибка фазы останавливает продвижение без автоматического
повтора или движения восстановления. Кооперативный лимит LOAD/UNLOAD —
900 секунд, собственных чтений — по две секунды. Эти сроки не прерывают ожидание
штатной библиотеки, действие MCU или уже отправленное движение.

Возврат команды не гарантирует пустую очередь Klipper: хвост LOAD может оставить
движение Z. Перед следующей операцией дождитесь фактической остановки.
Рецепты не добавляют автоматическое выключение нагрева; выключайте ненужный
нагрев отдельно. После отказа проверьте фактическое состояние материала,
позиции и нагревателя перед следующей командой.

<a id="reference-trial-results"></a>

## Проверка на базовом принтере

На K1C CFS Upgrade с cfs0 MCU 1.1.3 и Python принтера 3.8.2 проверены пассивный
запуск и файловый откат с кэшем. Предзагрузка проверена на всех четырёх слотах,
со свежими RFID/остатком и корректным отображением катушек на экране и в
Creality Print. Два последовательных полных цикла загрузки/выгрузки T1C
дали обычный выход пластика и возврат материала без ручной помощи.

Печать, контролируемые отказы/восстановление и другие версии MCU остаются
в [плане аппаратной проверки](implementation-plan.ru.md).
